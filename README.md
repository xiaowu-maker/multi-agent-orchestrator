# 多AI协作写代码说明书（新手友好版）

> 看不懂技术文档？看这份就对了。全是大白话。

---

## 这是啥？一句话说清楚

**让 AI 帮你写大项目时，把活拆给好几个 AI 分工干**，这样它不会写着写着忘了前面的代码。

比如你想做"一个完整的记账软件"，它不会一个 AI 硬扛到底，而是：

```
你 → 项目经理AI → 规划AI → 开发AI → 测试AI → 交回给你
```

---

## 打个比方：一家小公司

| 角色 | 比喻 | 干什么 |
|------|------|--------|
| 主 AI | **项目经理** | 不写代码，只分配任务、检查结果、向你汇报 |
| 规划 AI | 做规划的 | 把大项目拆成小任务，列个清单给你看 |
| 开发 AI | 干活的 | 按清单写代码 |
| 测试 AI | 质检员 | **真的运行**代码，检查有没有毛病 |
| 审查 AI | 老专家（可选） | 挑代码毛病，有"一票否决权" |

**AI 之间不直接聊天**，靠**写文件传话**（像传小纸条）：

- 干完活的 AI 写一张"我干了啥、为什么这么干"的小纸条（status.json），交给项目经理
- 下一个 AI 开工前，先看小纸条再干活

好处：每个 AI 开工都是**干净的新脑子**，只带小纸条上的记忆——不会聊着聊着忘事，还省算力（省钱）。

## 三个版本，你用哪个？

| 版本 | 适合谁 | 用起来多麻烦 |
|------|--------|-------------|
| 🅱 **Hermes 版** | 你平时用的就是这个 | ★ 零安装，说句话就能跑 |
| 🅰 **Claude Code 版** | 用 Claude Code 的人 | 装一次模板 + 复制一个文件 |
| 🅲 **dsh 版** | 用 dsh（DeepSeek）的人 | 跟 Claude Code 差不多 |

三个版本干的事一模一样，**只有"AI 之间怎么传话"的方式不同**（Hermes 和 Claude Code 靠小纸条；dsh 多一个"对讲机"，能直接喊之前干活的 AI）。

---

## 🅱 Hermes 版怎么用（最推荐，就 3 步）

**第 1 步**：打开 Hermes，直接说：

```
开发一个完整的XXX
```

（比如：开发一个完整的命令行 TODO 管理器，支持增删改查）

**第 2 步**：它会让你选一个"套餐"，选第一个就行：

| 套餐 | 内容 | 什么时候选 |
|------|------|-----------|
| standard | 计划→开发→测试 | ✅ 一般都用这个 |
| with-review | 再加一个挑毛病的老专家 | 代码质量要求高时 |
| minimal | 最简（直接开发→测试） | 需求已经很明确时 |
| ai-competition | 分析→实验→评估 | AI 比赛专用 |

**第 3 步**：剩下它自己干。只会在三个"检查点"停下来问你：

1. **计划列好了** → 它问你"Y)执行 N)修改"——你点头它才开工
2. **某个任务死活搞不定** → 停下来问你怎么办（跳过？换个思路？换人？）
3. **全部干完** → 给你总结（几个任务通过、几个失败、东西在哪）

就这么多。**你全程只需要回答几个选择题。**

> 想改设置（换模型、加角色、调并行数量）？那是进阶内容，见文末 MANUAL.md。

## 🅰 Claude Code 版怎么用（4 步）

**第 1 步**：装模板（**只用装一次**）

- Windows：打开 `templates/multi-agent/claude-code/` 文件夹，**双击 install.bat**
- Mac / Linux：在那个文件夹里打开终端，输入 `bash install.sh`

**第 2 步**：把 `~/.claude/templates/multi-agent/CLAUDE.md` **复制到你的项目文件夹里**

> 这个文件是给 AI 看的"工作须知"，它每次开工都会自动读。放对位置它才知道自己该干嘛。

**第 3 步**：在项目里对它说：

```
帮我开发一个XXX
```

**第 4 步**：跟 Hermes 版一样——选套餐、点头、等结果。

⚠️ **第 1 步不能省**：不装模板的话，它找不到规则文件，干到一半会卡住。

## 🅲 dsh 版怎么用（3 步）

**第 1 步**：把 `templates/multi-agent/dsh/CLAUDE.md` 复制到项目文件夹。
（如果 dsh 不支持这个文件，就手动建配置文件夹，详细步骤见 MANUAL.md）

**第 2 步**：说：

```
开发一个完整的XXX
```

**第 3 步**：跟上面一样。唯一区别：它修 bug 时**优先"喊原来干活的 AI 接着干"**（对讲机），喊不动了才用传纸条。不管哪种方式，它都会更新小纸条——因为纸条是最后的保命手段。

---

## 它怎么防 AI 偷懒骗你？（这套方案最值钱的地方）

AI 干活有时候会**吹牛**，比如没真跑就说"测试通过了"。这套方案有三个保险：

1. **交作业要验货**：AI 说"写好了"，项目经理会**真的去检查文件在不在**。不在？打回重做
2. **说"测试通过"必须拿出证据**：测试记录文件必须是**真的、有内容的**（有运行命令、有输出）。空文件 = 作弊 = 打回
3. **搞不定不许装懂**：AI 修了 3 轮还修不好，必须**老实停下来问你**，不许假装修好了（它撒谎的话项目经理会对照证据发现）

另外：每个任务修 3 轮还不行，它会升级给你处理，还给你一个"**换人**"选项——换个全新的 AI 从头干，有时候比让原班人马死磕更管用。

## 小白常见问题

**Q：小任务也要用这个吗？**
A：**不用**。写一个文件的小事直接让 AI 做。这套是给"大项目"（多模块、多文件）用的。

**Q：干到一半我关电脑了，怎么办？**
A：没事。它会**记账**（progress.yaml），下次你说"继续"它接着干。

**Q：AI 返回了一大段代码，而不是文件路径？**
A：提醒它："只报路径，别贴代码"。这是它的规矩——贴代码会把项目经理的脑子撑爆。

**Q：我不小心删了某个记录文件，会出事吗？**
A：大部分能自愈——它会从其他文件里把信息找回来。实在找不回的会标记"需要重新规划"并告诉你。

**Q：担心 AI 不听话、乱来？**
A：它每个关键节点都要**停下来问你**，你不点头它不往下走。你永远有最后决定权。
